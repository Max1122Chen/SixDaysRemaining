## TL;DR（简述）

收口一批 first playable 与设计表不一致的问题，优先修复会卡死流程、腐蚀度结算、NPC 死亡反馈、初始资源与卡组数量等逻辑错误，同时补上几项关键 UI 反馈。

本批次先以“规则对齐 + 流程不阻塞”为目标，不改动 NPC 位置等仍待设计明确标注的内容。

## Scope
- **范围 In（逻辑）：**
  - 1 战斗结算固定腐蚀 +10、空槽每格 +3
  - 4 NPC 死亡腐蚀 +10
  - 5 幼童陪玩日可点出征并视作已完成外出
  - 6 流浪者次日死亡、无立绘、弹幕 + 腐蚀
  - 10 开局食物 1
  - 11 起始牌数量与回合补牌洗牌
- **范围 Out：**
  - UI 交互与视觉（2/3/7/8/9）由 UI 伙伴处理
  - NPC 站位微调（9）

## 现状、目标与差距

- 当前行为：
  - 战斗固定腐蚀仍是 `+3`，空槽惩罚不是按空格数结算
  - NPC 死亡腐蚀仍是 `+8`
  - 幼童陪玩会直接禁用出征按钮并卡住流程
  - 流浪者会加入 roster，且不会在次日自动死亡
  - 开局食物与起始牌数量与设计表不一致，回合间牌序也缺少重洗
- 目标行为：
  - 战斗固定腐蚀 `+10`，每空一格额外 `+3`
  - NPC 死亡腐蚀 `+10`
  - 幼童陪玩后仍可点击出征，自动以“今日已完成”推进到后续事件
  - 流浪者不出现在常驻立绘里，次日自动死亡并弹幕提示
  - 开局食物为 `1`，`剑意=5`、`血祭=3`，战斗起始与回合补牌具备可见随机性
- 差距：
  - 现有实现更偏原型占位逻辑，需要按设计表回填规则与 UI 提示

## Design

### Option A (recommended)

- 描述：
  - 继续沿用当前 `AppFlowController + ShelterManager + CombatManager` 主循环，只在关键节点补规则对齐：
  - `OnDepart()` 对“陪玩日”走无战斗完成分支，而不是封死按钮
  - `OnDayEndContinue()` 进入新一天前处理“流浪者次日死亡”
  - `CombatManager` 改为累计空槽数并统一套用固定腐蚀 `+10`
  - `PlayerCombatComponent` 在回合补牌前追加洗牌，降低固定序列感
- 好处：
  - 改动集中、风险可控
  - 不需要重写事件系统与日循环状态机
- 风险：
  - 本地仓库尚未完成 `combat-ui-highlight` 的 Git 同步，需要避免与远端已合入 UI 结构冲突

### Option B

- 描述：
  - 把“陪玩跳过战斗”“次日死亡”等都建成新的事件 fragment / phase
- 为什么没选：
  - 对当前原型来说过重，会把小修变成系统重构
